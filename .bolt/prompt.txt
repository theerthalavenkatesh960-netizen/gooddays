PHASE 1 — Database Tables (PostgreSQL)
-------------------------------------------------
Create the following PostgreSQL tables for a 
Financial Life Tracker module:

1. financial_goals
─────────────────
id: UUID (PK)
name: VARCHAR(100)
target_amount: DECIMAL(12,2)
target_date: DATE
created_at: TIMESTAMP
is_active: BOOLEAN

2. investment_buckets
─────────────────────
id: UUID (PK)
name: VARCHAR(100)
category: ENUM(
  'EMERGENCY_FUND',
  'HEALTH',
  'TRAVEL',
  'MISCELLANEOUS',
  'WEALTH',
  'TRADING'
)
monthly_target: DECIMAL(10,2)
color_hex: VARCHAR(7)
icon: VARCHAR(50)
is_active: BOOLEAN
sort_order: INT
created_at: TIMESTAMP

3. monthly_tasks
────────────────
id: UUID (PK)
bucket_id: UUID (FK → investment_buckets)
title: VARCHAR(200)
description: TEXT
task_type: ENUM(
  'SIP_PAYMENT',
  'EMI_PAYMENT',
  'INSURANCE_REVIEW',
  'PORTFOLIO_REVIEW',
  'EMERGENCY_FUND_CHECK',
  'TRAVEL_FUND_CHECK',
  'CUSTOM'
)
amount: DECIMAL(10,2)
is_recurring: BOOLEAN
recurrence_day: INT (day of month)
is_active: BOOLEAN
created_at: TIMESTAMP

4. monthly_task_completions
────────────────────────────
id: UUID (PK)
task_id: UUID (FK → monthly_tasks)
month: INT
year: INT
is_completed: BOOLEAN
completed_at: TIMESTAMP
actual_amount: DECIMAL(10,2)
notes: VARCHAR(500)
created_at: TIMESTAMP

5. financial_rules
──────────────────
id: UUID (PK)
title: VARCHAR(200)
description: TEXT
category: ENUM(
  'INVESTMENT',
  'TRADING',
  'MINDSET',
  'LIFESTYLE'
)
display_style: ENUM(
  'BANNER',
  'CARD',
  'POPUP',
  'SIDEBAR'
)
is_active: BOOLEAN
sort_order: INT
created_at: TIMESTAMP

6. monthly_snapshots
─────────────────────
id: UUID (PK)
month: INT
year: INT
total_income: DECIMAL(10,2)
total_expenses: DECIMAL(10,2)
total_invested: DECIMAL(10,2)
emergency_fund_balance: DECIMAL(10,2)
travel_fund_balance: DECIMAL(10,2)
portfolio_estimated_value: DECIMAL(12,2)
notes: TEXT
created_at: TIMESTAMP

PHASE 2 — .NET Core API Controllers
---------------------------------------------------------------
Build the following .NET Core 8 Web API controllers
for a Financial Life Tracker module.
Use PostgreSQL with Entity Framework Core.
Follow clean architecture with:
→ Controllers
→ Services
→ Repository pattern
→ DTOs for all requests/responses

─────────────────────────────────────
CONTROLLER 1: BucketsController
─────────────────────────────────────
Endpoints:
GET    /api/buckets
       → Returns all active buckets
         with current month completion %

GET    /api/buckets/{id}
       → Returns single bucket with
         all tasks and completion status

POST   /api/buckets
       → Create new bucket
         (name, category, monthly_target,
          color_hex, icon)

PUT    /api/buckets/{id}
       → Update bucket details
         (configurable monthly target!)

DELETE /api/buckets/{id}
       → Soft delete (is_active = false)

─────────────────────────────────────
CONTROLLER 2: TasksController
─────────────────────────────────────
Endpoints:
GET    /api/tasks
       → Returns all active tasks
         with this month's completion status

GET    /api/tasks/monthly/{month}/{year}
       → Returns ALL tasks for that month
         with completion status
         grouped by bucket

POST   /api/tasks
       → Create new task
         (title, description, bucket_id,
          task_type, amount, is_recurring,
          recurrence_day)

PUT    /api/tasks/{id}
       → Update task details

POST   /api/tasks/{id}/complete
       → Mark task as complete for
         current month
         Body: { actual_amount, notes }

POST   /api/tasks/{id}/uncomplete
       → Undo completion for current month

DELETE /api/tasks/{id}
       → Soft delete task

─────────────────────────────────────
CONTROLLER 3: DashboardController
─────────────────────────────────────
Endpoints:
GET    /api/dashboard/current
       → Returns full dashboard data:
         {
           current_month: string,
           overall_completion_percent: number,
           buckets: [
             {
               id, name, category,
               color_hex, icon,
               monthly_target,
               completion_percent,
               tasks_total,
               tasks_completed,
               tasks: [...]
             }
           ],
           monthly_snapshot: {...},
           rules: [...],
           streak: number,
           (how many months 100% completed)
           upcoming_tasks: [
             tasks due in next 7 days
           ],
           missed_tasks: [
             tasks not completed from
             previous month
           ]
         }

GET    /api/dashboard/history
       → Returns last 12 months
         completion data for chart

─────────────────────────────────────
CONTROLLER 4: RulesController
─────────────────────────────────────
Endpoints:
GET    /api/rules
       → Returns all active rules
         grouped by category

POST   /api/rules
       → Create new rule

PUT    /api/rules/{id}
       → Update rule
         (title, description,
          display_style, is_active)

DELETE /api/rules/{id}
       → Soft delete

─────────────────────────────────────
CONTROLLER 5: SnapshotsController
─────────────────────────────────────
Endpoints:
GET    /api/snapshots
       → Returns all monthly snapshots
         sorted newest first

GET    /api/snapshots/{month}/{year}
       → Returns specific month snapshot

POST   /api/snapshots
       → Create or update monthly snapshot
         (upsert by month+year)
         Fields:
         total_income,
         total_expenses,
         total_invested,
         emergency_fund_balance,
         travel_fund_balance,
         portfolio_estimated_value,
         notes

─────────────────────────────────────
AUTO-GENERATE MONTHLY TASKS SERVICE:
─────────────────────────────────────
Create a background service that runs
on 1st of every month:

→ Checks all recurring tasks
→ Auto-creates task_completions entries
   for the new month with is_completed=false
→ This ensures every month starts
   with a fresh task checklist!
