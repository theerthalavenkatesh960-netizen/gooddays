Context:
I have a React/TypeScript app using Clerk for Google OAuth and a custom JWT auth system. After Google OAuth completes, the user is created in Clerk and the backend, but the app stays on the login page instead of navigating to /.
Files involved:

src/contexts/AuthContextApi.tsx — custom JWT AuthProvider, reads session via api.getSession() on mount
src/lib/api.ts — contains getSession() which may be making a backend call instead of reading localStorage
src/pages/ClerkCallback.tsx — after OAuth, writes gd_session to localStorage then does window.location.href = '/'
src/pages/Login.tsx — has useEffect(() => { if (user) navigate('/') }, [user]) which redirects if user is truthy

The bug:
ClerkCallback writes the session to localStorage as gd_session with shape { access_token: string, user: { id, email, name } }, then forces a full page reload via window.location.href = '/'. On reload, AuthContextApi.checkSession() calls api.getSession(). If api.getSession() makes an async backend call that fails silently, or doesn't read from localStorage, user stays null, loading becomes false, and the Login page's useEffect does nothing because user is still null — so the user stays stuck on login.
Required changes — implement all of these:

src/lib/api.ts — Make getSession() a synchronous function that only reads from localStorage:

tsexport const getSession = (): { access_token: string; user: { id: number; email: string; name?: string } } | null => {
  try {
    const raw = localStorage.getItem('gd_session');
    if (!raw) return null;
    return JSON.parse(raw);
  } catch {
    return null;
  }
};

src/contexts/AuthContextApi.tsx — Add setSessionFromOAuth to the context interface and implementation:

ts// Add to AuthContextType interface:
setSessionFromOAuth: (token: string, user: User) => void;

// Add inside AuthProvider:
const setSessionFromOAuth = (token: string, userData: User) => {

  setSession(payload);
  setUser(userData);
};
