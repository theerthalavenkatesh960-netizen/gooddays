Goal

Create a robust user memory architecture for AI context generation.
Replace fragile “single giant file per user” approach with structured memory layers.
AI should receive concise, relevant context per prompt: stable profile + recent state + key events.
Hard requirements

Memory model
Stable profile memory: long-lived user traits, preferences, constraints, goals, motivation style.
Dynamic state snapshots: daily and weekly aggregate state.
Episodic memory events: notable moments, trends, milestones, regressions.
Context retrieval logs: record what memory was assembled for each AI request.
PostgreSQL design
Create schema and entities for:
ai_user_profile_memory
ai_user_state_snapshot_daily
ai_user_state_snapshot_weekly
ai_user_event_memory
ai_prompt_context_log
ai_memory_update_job
Add proper foreign keys to user id.
Add indexes for user_id + created_at desc retrieval patterns.
Partition high-volume tables by time (monthly or quarterly), especially events/logs/jobs.
Add idempotency keys and constraints for jobs to avoid duplicate processing.
Update pipeline
Implement background memory update pipeline that ingests from existing domains:
tasks, workout, routine, finance, journal, reminders, daily tracking.
Memory updates must be incremental and idempotent.
Use queue table and worker/hosted service pattern in backend.
Include retry strategy, dead-letter handling, and observability fields (attempt_count, last_error, processed_at).
Context assembly service
Build a service method:
BuildContext(userId, userPrompt, contextBudget)
It should:
fetch profile memory
fetch latest daily and weekly snapshots
fetch top relevant episodic events
compose compact context JSON and text summary
respect token budget
Add clear ranking rules for relevance without vector DB:
recency score
domain match score
severity/importance score
frequency score
API endpoints
Add endpoints:
GET user memory profile
PUT user memory profile
POST trigger memory rebuild
POST build ai context for prompt
GET memory diagnostics summary
Require authorization and user isolation.
Frontend integration
In settings, add user controls for AI memory:
enable/disable memory domains
privacy controls
manual memory refresh
view summary of stored memory
In dashboard, optionally surface “AI memory freshness” indicator and last updated time.
Extend frontend API client methods accordingly.
Privacy and safety
Per-user strict data isolation.
Data minimization in prompt context.
User can delete or reset their memory profile.
Log context assembly metadata without leaking sensitive raw payloads unnecessarily.
Add clear retention policy support.
Performance and scale
Design for 10k users and multi-year history.
No full-history scan on each prompt.
Retrieval must be bounded and index-friendly.
Use precomputed snapshots to keep latency low.
